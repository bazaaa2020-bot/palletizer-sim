# Реальные 3D-модели в тренажёре

Ответ на вопрос «у меня есть STEP-модель кобота, как поставить её в симуляцию с её
параметрами». Коротко: STEP в браузер напрямую не грузится, и главное — в STEP нет
кинематики. Нужны два разных источника: **геометрия** (из STEP) и **паспорт** (из
документации или URDF).

## Почему не STEP напрямую

STEP (ISO 10303, `.stp` / `.step`) — это точная B-rep геометрия: NURBS-поверхности,
обрезки, топология. Видеокарта рисует только треугольники, поэтому модель сначала надо
**тесселировать**. three.js штатного загрузчика STEP не имеет.

Рабочий формат для браузера — **glTF 2.0 (`.glb`)**: треугольники, материалы, иерархия
узлов, сжатие. Именно иерархия узлов и важна: в ней мы задаём звенья робота.

## Маршрут STEP → glTF

| Инструмент | Чем хорош | Чем неудобен |
|---|---|---|
| **FreeCAD** | бесплатный, читает STEP, экспортирует glTF/OBJ, скриптуется на Python | тесселяция настраивается вручную |
| **CAD Assistant** (Open CASCADE) | бесплатный, быстрый STEP → glTF | GUI, не скриптуется |
| **Blender** + аддон STEPper | удобная правка сеток и осей | аддон сторонний |
| **occt-import-js** (OCCT в WebAssembly) | читает STEP **прямо в браузере** | +2–3 МБ рантайма, тесселяция на клиенте |

Пример на FreeCAD (консольный режим):

```python
import FreeCAD, Import, Mesh
doc = FreeCAD.newDocument()
Import.insert("cobot.step", doc.Name)
# 0.1 мм по хорде — компромисс между видом и числом треугольников
Mesh.export([o for o in doc.Objects if hasattr(o, "Shape")], "cobot.obj")
```

Дальше `.obj` → `.glb` в Blender или через `obj2gltf`.

**Считайте треугольники.** Заводская STEP-модель кобота после тесселяции легко даёт
1–3 млн треугольников: там резьба, фаски, крепёж. Для тренажёра нужно 20–60 тысяч на
всего робота. Уберите внутренние детали и упростите сетку (Decimate в Blender).

## Кинематика: в STEP её нет

STEP описывает форму, а не то, как детали двигаются. Чтобы робот шевелился, модель надо
**разрезать на звенья** — для шестиосевого это 7 тел: основание и J1…J6.

Для каждого звена нужны:

- **начало координат в оси сустава** (не в центре масс и не в углу габарита) — иначе
  звено будет вращаться не вокруг того;
- **направление оси вращения**;
- родитель в цепочке: основание → J1 → J2 → … → J6 → фланец.

В Blender: выделяете тело звена, ставите 3D-курсор на ось сустава, `Object → Set Origin →
Origin to 3D Cursor`, затем родительство `Ctrl+P`. Экспорт в glTF сохраняет эту иерархию,
и в three.js остаётся крутить `scene.getObjectByName('J2').rotation.z = …`.

## Параметры: URDF, а не STEP

Скорости, ускорения, пределы углов, грузоподъёмность, вылет — это паспорт. Формат, где
всё это лежит вместе с ссылками на сетки, — **URDF** (из ROS). Многие производители
коботов публикуют URDF официально.

```xml
<joint name="shoulder_lift" type="revolute">
  <parent link="base"/><child link="upper_arm"/>
  <origin xyz="0 0 0.163" rpy="0 1.5708 0"/>
  <axis xyz="0 1 0"/>
  <limit lower="-3.14" upper="3.14" effort="150" velocity="3.14"/>
</joint>
```

`origin` — где сустав, `axis` — вокруг чего крутится, `limit/velocity` — рад/с,
`effort` — Н·м. Ускорения в URDF нет, его берут из руководства по программированию.

Практичный порядок: **геометрию берём из STEP, оси и пределы — из URDF, а скорости и
ускорения — из паспорта**. Если URDF нет, оси придётся снимать с чертежа.

## Что это значит для этого тренажёра

Сейчас робот нарисован процедурно (`src/02-view3d.js`): цилиндры и коробки по вылету из
каталога. Плюс — тренажёр остаётся **одним самодостоятельным HTML-файлом**, который
открывается без сервера. Внешняя модель этот принцип ломает, поэтому есть три варианта:

1. **Встроить `.glb` в HTML как base64.** Файл остаётся один. Цена — размер: сейчас
   сборка ~200 КБ, скромная модель кобота добавит 1–3 МБ (base64 ещё +33 %).
2. **Грузить модель рядом с файлом или по ссылке.** Нужен `GLTFLoader` (он не входит в
   ядро three.js) и правило «если модель не загрузилась — рисуем процедурно, как сейчас».
   Самодостаточность теряется, зато файл остаётся лёгким.
3. **Оставить процедурную геометрию, но вынести размеры звеньев в каталог.** Модель
   робота описывается 8–10 числами (высота колонны, длины плеча и предплечья, габариты
   суставов, вылет кисти). Для учебной ячейки этого достаточно, а параметры движения
   (скорость, ускорение, рывок, пределы) уже есть в конфигураторе.

Разумный порядок — сделать 3 сразу, а 2 добавить как опцию: описание робота в каталоге
получает необязательное поле `model` со ссылкой на `.glb`, и если файл есть, он заменяет
процедурные звенья, подхватывая ту же кинематическую цепочку. Тогда одна и та же
математика работает и с «палочками», и с заводской моделью.

Отдельно про **конвейеры и ограждение**: здесь заводская модель почти не нужна. Рольганг,
сетчатая панель и световая завеса — это несколько параметров (длина, ширина, шаг роликов,
высота панели), и процедурная геометрия даёт правильную картинку без мегабайтов.
