# Тренажёр РТК паллетизации — инструкции для Claude Code

Учебно-инженерный тренажёр роботизированной ячейки паллетизации: конфигуратор, инженерные
расчёты, симуляция работы ячейки с ПЛК-логикой и 3D-вид. Весь интерфейс на русском языке.
Проект ведёт Константин (начальник конструкторского отдела, интегратор робототехники);
цель — разобраться в промышленной безопасности, логике ПЛК, приводах и архитектуре АСУ ТП
на примере реальной ячейки и получать из тренажёра состав системы под конкретную задачу.

## Команды

```bash
npm install     # один раз: jsdom для тестов
npm run build   # склеивает src/ → dist/palletizer-sim.html и проверяет синтаксис
npm test        # сборка + дымовой тест в jsdom (test/headless.js)
npm run serve   # http://localhost:8080 — посмотреть собранный файл локально
```

**Перед завершением любой задачи обязательно запусти `npm test`.** Тест проверяет переходы
PackML, укладку, обмен паллет, пополнение прокладок, реакцию на завесу и аварийный стоп.
Если менял поведение намеренно — поправь и тест.

## Устройство проекта

Результат — **один самодостаточный HTML-файл** `dist/palletizer-sim.html`, который
открывается в браузере без сервера и публикуется как артефакт. Сборщик просто склеивает
части из `src/` в фиксированном порядке (см. `build.js`). Правь **только файлы в `src/`**,
`dist/` пересобирается.

| Файл | Что внутри |
|---|---|
| `src/index.head.html` | `<head>`, CSS-переменные тем, разметка пяти вкладок, открывающий `<script>` |
| `src/01-catalog-and-calc.js` | Каталоги (роботы, коробки, паллеты, конвейеры, захваты, присоски), генератор схем укладки, расчёт захвата, компоновка, `derive()` — главный расчёт конфигурации, список сигналов, спецификация, оптимизатор, планировщик артикулов, текст алгоритма |
| `src/01b-safety-pl.js` | Performance Level по ISO 13849-1: граф рисков, архитектуры цепи, MTTFd, DCavg, CCF, диаграмма рис. 5, таблица 11; функции безопасности собираются из конфигурации |
| `src/01c-risk-12100.js` | Оценка риска по ISO 12100: реестр опасностей из конфигурации, четыре элемента риска, матрица классов, меры трёх шагов, остаточный риск |
| `src/01d-oee.js` | Смена и OEE: категории простоев по PackML, готовность/производительность/качество, Парето причин, проекция на смену, сценарии тревог |
| `src/01e-grafcet.js` | Логика ПЛК как данные: словари действий и условий, эталонная программа, интерпретатор, проверка структуры, сравнение с эталоном |
| `src/01f-mix.js` | Смешанная паллета: рецепт ярусов, разворот в список слоёв, итоги по слоям, проверки рецепта |
| `src/02-view3d.js` | three.js r128 (с CDN): сцена, кинематика робота, паллеты со слоями, тележки и люди |
| `src/03-ui-and-sim.js` | Конфигуратор (UI), вкладка архитектуры, движок симуляции (PackML, GRAFCET, агенты обмена), задания, справочник, инициализация |
| `src/04-report.js` | Обмен конфигурацией (сохранение и загрузка `.json`), отчёт по ячейке, 2D-схема участка с габаритными размерами |
| `src/index.tail.html` | Закрывающие теги |

Ключевые объекты: `CFG` — конфигурация (сохраняется в localStorage под ключом `pal-sim-cfg4`),
`derive(CFG)` → `DD` — все расчёты, `S` — состояние симуляции, `GG` — геометрия плана,
`V3` — 3D-сцена. `buildSim()` пересобирает симуляцию, `renderCfg()` — конфигуратор,
`renderArch()` — архитектуру и текст алгоритма, `render()` — кадр плана, `render3D()` — кадр 3D.

## Правила

- Никаких сборщиков, фреймворков и npm-зависимостей в рантайме: только ванильный JS,
  SVG и three.js с cdnjs. Новые зависимости — только по согласованию.
- Цвета — через CSS-переменные из `:root` (светлая и тёмная темы), не хардкодить.
- Весь текст интерфейса и комментарии — по-русски, термины отраслевые (ЧП, КБ, завеса,
  мьютинг, PackML, GRAFCET).
- **Переписка с пользователем — тоже по-русски**: ответы, вопросы, отчёты о работе.
  По-английски остаются только технические идентификаторы — имена переменных и функций,
  файлы, ветки, сообщения коммитов.
- Инженерные формулы не «подгонять»: если меняешь методику, опиши её в `docs/methodology.md`.
- Не переформатировать файлы целиком (стиль плотный, много однострочников) — точечные правки.
- localStorage используется для `CFG` и выполненных заданий; в артефактах claude.ai
  браузерное хранилище может быть недоступно — все обращения обёрнуты в try/catch, так и оставлять.
- 3D-вид должен корректно отключаться, если three.js не загрузился или нет WebGL
  (сообщение в `#v3msg`) — это проверяется тестом.

## Что уже сделано (v4)

Конфигуратор роботов/захватов/коробок/конвейеров, схемы укладки с перевязкой, расчёт
вакуумного захвата, групповой захват до 8 коробок, 1–2 робота, 1–4 станции, магазины
прокладок, режимы прокладок, обмен паллет (рохля, погрузчик, AMR, конвейер паллет),
подача пустых паллет роботом из стопки, симуляция людей и тележек, ISO 13855, генерация
сигналов и спецификации АСУ ТП, оптимизатор конфигурации, планировщик артикулов по
методике «циклов на паллету», вкладка «Алгоритм работы» человеческим языком, 3D-вид.

Добавлено сверх v4: **подбор групп захвата по форме слоя** (`docs/roadmap.md`, п. 1).
У захвата появился шаг зон — фиксированный (балка, группа только ряд вплотную, прежнее
поведение) или регулируемый: зоны разводятся в прямоугольный блок nc × nr под форму слоя.
Блок стоит двух перестроений на ход, планы «рядами» и «блоками» сравниваются по времени.
Ключевые места: `makeGroups` и `choosePattern` в `src/01-catalog-and-calc.js`, шаги
`shift` / `unshift` в цикле робота в `src/03-ui-and-sim.js`.

Добавлено сверх v4: **реалистичная укладка** (`docs/roadmap.md`, п. 9). Появился раздел
настроек движений (`CFG.motion`: скорость подвода, высота точки подхода, скорость
вертикали, время нарастания ускорения, скорость доворота кисти). Цикл робота разложен на
фазы — подход, опускание на подводе, захват, отрыв, перенос с доворотом, опускание,
касание, подъём над слоем; такт считается по этим же фазам, поэтому симуляция и расчёт
сходятся. Ключевые места: `moveTime` и блок такта в `derive()` в
`src/01-catalog-and-calc.js`; `rampV`, `moveZ`, `turnTo` и шаги `down*` / `up*` в
`src/03-ui-and-sim.js`; доворот груза (`carry.rotation.y`) в `src/02-view3d.js`.

Добавлено сверх v4: **3D-вид приведён к реальным моделям**. Ограждение — сетчатые панели
в стойках с проёмами под конвейеры и обмен, в проёмах световые завесы с датчиками
мьютинга, дверь на петле с замком. Робот — шестиосевой кобот с корпусами суставов.
Погрузчик стоит снаружи и заводит в проём только вилки. Геометрия проверяется не на глаз:
`fenceHit` считает точку проёма на линии ограждения, а сверка нарисованного инструмента с
состоянием симуляции даёт расхождение в пределах 2 мм.

Исправлено: робот больше не бросает начатую паллету, когда рядом освобождается соседняя
станция (`byStarted` в `src/03-ui-and-sim.js`), и не проносит груз над чужой стопой —
в плане он идёт не ниже `zSafe`.

Добавлено сверх v4: **логистика обмена без конфликтов** (`docs/roadmap.md`, п. 15). У каждой
позиции в `layout()` считается маршрут подъезда (`slot.route`, `slot.gate`, `slot.acc`,
`slot.park`) с проверкой коридора шириной с технику; тележки идут этим маршрутом, а не по
прямой. При двух роботах станции получают углы, отвёрнутые от соседа, магазины смотрят в
межроботный проезд, ширина проезда заложена в `pitch`. Запертые позиции — в `LY.blocked`
и в предупреждениях.

Добавлено сверх v4: **вкладка «Отчёт и обмен»** (`docs/roadmap.md`, п. 16). Конфигурация
выгружается и загружается файлом `.json` (`cfgJSON` / `cfgFromJSON`, формат
`palletizer-sim/config@1`, чужие поля отбрасываются, свои дополняются из `DEF`, битый файл
отвергается). Отчёт собирает исходные данные, результаты расчёта, схему участка с
размерными линиями (`planSVG`), снимок 3D-компоновки, спецификацию, список сигналов и
замечания; скачивается отдельным самодостаточным html или печатается в PDF.

Добавлено сверх v4: **тара произвольной формы, направляющие и техническое зрение**
(`docs/roadmap.md`, п. 10–12). У тары есть форма (`SHAPES`) и материал (`MATS`), у конвейера
— способ подачи (`INFEED`) и базирование (`ALIGN`), у ячейки — система зрения (`VISION`).
Цепочка: разброс на подаче → направляющие → зрение → допуск захвата (`pickTol`, `baseCalc`).
Выход за допуск даёт промахи в симуляции. Пригодность захвата под тару — `gripFit` /
`gripBest`, добавлен магнитный захват.

Добавлено сверх v4: **Performance Level по ISO 13849-1** (`docs/roadmap.md`, п. 2). Вкладка
«Безопасность и PL»: граф рисков (`CFG.pl.S/F/P`) даёт PLr, архитектура цепи (категории
B, 1, 3, 4), EDM, наработка и число срабатываний за смену, чек-лист CCF с порогом 65
баллов. Функции безопасности собираются из самой конфигурации (`sfList`), по каждой
считается MTTFd канала из B10d, DCavg, PL подсистемы по рис. 5 и PL функции по таблице 11.
Результат — на столбчатой диаграмме, в замечаниях конфигуратора и в отчёте. Ключевые
места: `src/01b-safety-pl.js` целиком, `D.pl=plCalc(c,D)` в `derive()`, `renderPL` в
`src/03-ui-and-sim.js`, раздел отчёта в `src/04-report.js`.

Добавлено сверх v4: **выгрузка таблиц в CSV** (`docs/roadmap.md`, п. 3). Семь таблиц

Добавлено сверх v4: **оценка риска по ISO 12100** (`docs/roadmap.md`, п. 5). Вкладка

сверяется с графом рисков вкладки «Безопасность и PL». Ключевые места:
`src/01c-risk-12100.js`, `D.risk=riskCalc(c,D)` в `derive()`, `renderRisk` в
`src/03-ui-and-sim.js`, таблица `risk` в `CSV_TABLES` и раздел отчёта в `src/04-report.js`.

Добавлено сверх v4: **редактор логики ПЛК** (`docs/roadmap.md`, п. 4). Последовательность
ячейки вынесена из кода в данные (`CFG.plc`): две диаграммы GRAFCET — G1 «цикл укладки» на
каждого робота и G2 «обмен паллет» на каждую станцию. `plcTick` исполняет их на каждом такте,
а подача, выбор задания роботом (`plcJob`), вызов обмена и лампа читают выданные разрешения.
Эталон (`grafRef`) копируется в свою программу и правится в таблице; `grafCheck` проверяет
структуру, `grafDiff` сравнивает с эталоном. Цепи безопасности программе не подчиняются.
Ключевые места: `src/01e-grafcet.js`, `plcInit` / `plcTick` / `plcJob` / `renderGraf` в
`src/03-ui-and-sim.js`, таблица `plc` в `CSV_TABLES` и раздел отчёта в `src/04-report.js`.

Добавлено сверх v4: **смешанная паллета** (`docs/roadmap.md`, п. 6). `CFG.mix` — рецепт из
ярусов (артикул, число слоёв, лист под ярусом); `mixCalc` разворачивает его в список слоёв
`D.mix.rec`, который станция получает как `s.rec`. Моно-паллета — тот же список из
одинаковых слоёв (`monoRec`), поэтому ветвлений в симуляции нет: слой знает свою схему
(`patOf`), свою тару (`biOf`) и свой конвейер (`convOf`). Итоги и такт суммируются по слоям,
3D красит слои по артикулам. Ключевые места: `src/01f-mix.js`, разворот рецепта в `derive()`,
`recAt` / `patOf` / `biOf` / `convOf` / `recH` в `src/03-ui-and-sim.js`, `buildStation3` в
`src/02-view3d.js`, панель `#cfgMix`, таблица `mix` в `CSV_TABLES` и раздел отчёта.

Про заводские модели STEP/glTF и кинематику — `docs/models-3d.md`.
